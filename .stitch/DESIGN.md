# Design System: QuickFork Compact Infographic SaaS

## 1. Product Frame

QuickFork is a repo-to-infographic SaaS tool for developers who need a cold-start launch asset quickly. The landing page should feel like a working product surface: paste a repo, choose output basics, generate an infographic, then reuse it for README and social distribution.

## 2. Visual Theme

Use a clean white workspace, crisp borders, dark primary actions, and compact mono labels. Avoid command-center metaphors, fake metrics, decorative badges, and long explanatory text. The page should read as simple, precise, and high-completion.

## 3. Color Roles

- **Canvas White** (#ffffff) - page and tool surfaces.
- **Charcoal Ink** (#02020f) - primary text and controls.
- **Soft Ink Wash** (rgba(2, 2, 15, 0.58)) - helper copy and labels.
- **Deep Product Navy** (#010120) - primary actions and dark workflow sections.
- **Product Green** (#178f74) - pipeline state and focused emphasis.
- **Hairline Border** (rgba(2, 2, 15, 0.10)) - panel, grid, card, and form dividers.

## 4. Typography

Use the existing QuickFork sans stack for all H1/H2/H3 headings with weight 760, tight line-height, and zero letter spacing. Use the mono stack for output chips, step labels, format tags, and metadata.

## 5. Hero Requirements

- H1: "Repo in. Infographic out."
- Subtitle: one sentence explaining the GitHub repo to README-ready infographic and social copy workflow.
- Output rail: Infographic, README, X / LinkedIn, Square card.
- Generator: repo URL input, Generate package button, language toggles, and ratio selector.
- Right visual stage: generated infographic preview, compact format stack, and a simple Repo -> Infographic -> Share pipeline.
- Product animation: separate demo section below the Hero, never inside the Hero result panel.
- Header: QuickFork brand descriptor is "Repo-to-social tools"; Features has a compact dropdown for current and future repo-to-SaaS tools; account CTAs are allowed, but no product or function CTA belongs in the Header.

## 6. Section Requirements

Features should explain the three-step flow: Repo, Infographic, Distribute. Workflow should stay operational: Input, Generate, Export. Proof should be short and practical: no fake traction, source labels, edit before share, export ready.

## 7. Stitch Iteration Notes

If Stitch produces a generic SaaS hero, push it back toward the actual generator and visual output. If it produces an over-dense command surface, simplify it into a clean tool workflow. The best result should feel like a developer can complete the first repo-to-infographic run without reading a paragraph.
